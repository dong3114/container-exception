### 1.1 운영 콘솔 공통 틀 (T-135 — 1차 제품 UI, 확정 아님)

- 왼쪽 메뉴(업무 흐름 순서): **개요** · **예외** · **복구 실행** · **운영 입력**(`planning.input` · 공개 데모 제외) · **시스템**(`system.monitor`). 메뉴 옆 숫자 = 사람 조치 수 · 진행 중 예외 수 · 진행 중 복구 수(Backend 기록에서 셈). 연락 · 정보 · 계획은 페이지가 아니라 **복구 실행 안의 탭**(한 실행의 일)
- 위 머리: 배포 모드 배지(PUBLIC PORTFOLIO DEMO · PRIVATE STAGING · PRODUCTION · LOCAL) · 전체 시스템 상태(누르면 시스템) · "업데이트 중 / HH:MM:SS 기준"(다시 읽는 동안 화면을 지우지 않음) · [+ 새 실제 실행] · 사용자 이름 · 역할 · [로그아웃 / 데모 종료]
- 주소: `/?view=exceptions|recovery|inputs|system` · `&run=<실행 id>`(새로 고침해도 같은 화면). `/` 의 의미(운영 콘솔)는 바뀌지 않음
- 반복 모양: 숫자 카드(지금 값만 — 비교치 · 추세 없음) · 빈 상태(무엇이 없고 다음에 무엇이 생기는지) · 안내 상자(정보 · 경고 · 위험) · 세로 Timeline · 상태 카드(정상 ✓ · 지연 ! · 장애 ✕ · 사용 안 함 –)
- `/demo` · `/prototype` 은 이 틀을 쓰지 않음(성격이 다름 — 체험 · 옛 재생)

공통: 5초마다 다시 읽기(화면이 안 보이면 건너뜀 · 겹쳐 부르지 않음) · 권한(`/auth/me` 의 `permissions`)으로 버튼을 숨기거나 끔(최종 판정은 Backend 401 · 403) · 오류는 코드를 쉬운 말로 + 펼치면 코드 · HTTP · request id · 상태를 색만으로 나타내지 않음(기호 · 글자 함께) · WebSocket 없음.

## 3. 화면 상세

### SCR-01 로그인 · 공개 데모 소개
- 목적: 세션을 만든다 · 공개 배포면 처음 방문자를 데모로 안내
- 접근: 누구나 · 진입: 세션이 없을 때
- 영역: (일반) 아이디 · 비밀번호 · [로그인] / (포트폴리오 모드) 소개 카드(CERA 란 · 흐름 · 기술) · "이 데모에서 무엇이 진짜인가"(검증 범위 · Mock · 합성 · 녹화 재생) · [데모 시작] · 접힌 "관리자 로그인"
- 조회: `GET /auth/me`(401 이면 이 화면) · `GET /auth/demo-session`(있으면 포트폴리오 모드)
- Action: 로그인 → `POST /auth/login` / 데모 시작 → `POST /auth/demo-session` → `/demo`
- Error: 로그인 실패(계정 존재 여부 숨김) · 잠시 막힘 · 데모 준비 안 됨
- 비고: 데모 종료(로그아웃) 시 소개 화면으로 돌아감
- T-135: 소개를 짧게 — CERA 가 푸는 문제 한 단락 · [데모 시작] · "이 데모에서 체험할 것"(5줄) · "이 데모에서 무엇이 진짜인가"(Mock · 합성 · 녹화 재생 · 별도 환경 검증 범위) · 기술 한 줄 · 접힌 관리자 로그인

### SCR-02 운영 콘솔 상단 · 개요
- T-135: 공통 틀(1.1절). **개요** = 숫자 카드 6개(진행 중 예외 · 오늘 자동 탐지 · 사람 조치 대기 · 진행 중 복구 · 승인 대기 계획 · 검토 필요 회신 — 값만, 일부는 눌러서 해당 메뉴로) → 왼쪽 "지금 해야 할 일" · 오른쪽 "현재 예외"(진행 중만, [전체 · 이력 보기]) · "복구 진행"(사람 조치 · 진행 중 먼저 5건) · "시스템"(정상이 아니면 이유)
- T-133: 세션 줄에 **모드 배지**(PUBLIC PORTFOLIO DEMO · PRIVATE STAGING · PRODUCTION · LOCAL). 상단 상태는 `system.monitor` 가 있으면 전체 상태 한 개("시스템 정상" · "시스템 일부 지연 · 대체 경로로 운영 중" · "시스템 사람 조치 필요" · "시스템 중단" — 누르면 SCR-19), 없으면 "✓ 서비스 연결됨" 한 줄. 업무 숫자 6개: 진행 중 예외 · 오늘 자동 탐지 · 사람 조치 대기 · 진행 중 복구 실행 · 승인 대기 계획 · 검토 필요 회신
- 영역(T-132 전): (포트폴리오) PORTFOLIO DEMO 띠 — 합성 데이터 · 외부 메일 Mock · AI 녹화 재생 · [단계별 체험] · [운영 콘솔] / 세션 줄(이름 · 역할 · 로그아웃 또는 데모 종료) / 시스템 상태("✓ Backend · DB 정상" · "✓ 실행 큐" 또는 "! 실행 큐 없음(폴링으로 동작)" · "! Agent Runtime 응답 없음" · "✕ Backend 연결 안 됨")
- 조회: `GET /health` · `GET /agent-runs/runtime`
- 개요 숫자 줄(T-132): 진행 중 예외 · 오늘 탐지 · 사람 대기 · 진행 중 복구 실행 — `GET /exceptions` · `GET /planning/runs` 에서 계산

### SCR-03 지금 해야 할 일
- 목적: 사람이 할 일을 한곳에(같은 일은 한 번만)
- 영역: 할 일 목록(아이콘 · 제목 · 설명 · [열기])
- 항목 유형(코드 → 화면 문구): `HUMAN_APPROVAL_REQUIRED` "문의 초안 승인이 필요합니다" · `AWAITING_SEND_REQUEST` "승인된 문의의 발송 요청이 필요합니다" · `REPLY_REVIEW_REQUIRED` "답장이 왔지만 AI 가 내용을 확정하지 못했습니다" · `AWAITING_FACT_VERIFICATION` "임시 값의 확인이 필요합니다" · `AWAITING_PLAN_DECISION` "복구 계획 승인이 필요합니다" · `CONTACT_REGISTRATION_REQUIRED` "연락 가능한 담당자가 없습니다" · `CONTACT_SELECTION_REQUIRED` "연락할 담당자를 선택해야 합니다" · `HUMAN_ACTION_REQUIRED` "문의 초안을 고쳐야 합니다" · 후속 담당자 필요 · (T-132 · T-133) Agent 가 아직 없는 자동 탐지 실행 "복구 조사를 시작해 주세요"(버튼 [Agent 시작] → Agent 탭의 기존 시작 양식)
- 조회: `GET /agent-runs` · `GET /communication/drafts` · `GET /communication/inbound` · `GET /planning/runs/{runId}/plans`
- Action: [열기] → 해당 실행 · 탭 · 항목으로
- Empty: 할 일 없음 표시
- T-135: 항목마다 **종류 표시**(시작 · 승인 · 발송 · 검토 · 선택 · 수정 · 확인 — 심각도가 아님, Backend 에 심각도 없음) · 이유 · 대상 · 실행 · **발생 시각**(기록에 있을 때만) · 버튼 하나

### SCR-04 복구 실행 목록 · 새 실제 실행
- 영역: 묶음(사람 조치 필요 · 진행 중 · 완료 · 중단/오류) · 실행마다 시뮬레이션 배지 · [자동 탐지] 배지(`source = AUTO_DETECTED`) + 예외 한 줄("창고 A 수용량 부족 · 10-13 예정 20 / 가능 8 · 영향 12대", 해소되면 "해소됨") · Agent 상태 · 대기 사유 · 현재 판 / [+ 새 실제 실행] (`planning.input` 만)
- 조회: `GET /planning/runs` · Action: 새 실제 실행 → `POST /planning/runs`

### SCR-05 실행 상세 — 개요
- T-135 **복구 실행 머리**(모든 탭 위에 늘): 상태 묶음 · 제목("창고 A 수용량 부족 복구" / 예외 없는 실행은 실행 이름) · 실제/시뮬레이션 · 발생 원인 · 대상 시설 · 영향 수량(예정 / 가능) · 출처(자동 탐지 · 사람 · 시나리오) · 시작 시각 · Agent · 계획
- 영역: 지금 하는 일 · 기다리는 것 · 마지막 작업 · 다음 예상(기록된 단계로만) · 확인이 필요한 정보 표 · 현재 판 요약
- 조회: `GET /agent-runs/{id}` · `GET /planning/runs/{runId}/plans`

### SCR-06 Agent (+ 연락처 문제 해결)
- 영역: Agent 상태 · 대기 사유 쉬운 말 · [Agent 시작] (수량 등 시작 매개변수) · [다시 확인] · [취소] / 연락처 문제 패널:
  - 등록 필요(관리자): 운영 회사 등록 · 담당자 이름 · 주소 · "CERA 밖에서 확인함" · [담당자 등록 · 승인]
  - 선택 필요: 그 회사 담당자만 표시 · 쓸 수 없는 주소(중지 · 퇴사 · 미승인)는 상태와 함께 보이되 선택 불가 · **처음에 아무것도 선택 안 됨** · [이 담당자로 진행]
  - 트럭 풀 소유 운송사: 그 풀에 이미 나간 문의의 받는 회사로 추정(없으면 운송사 목록 + 안내)
- T-135: 그래프 노드 이름 대신 운영자 말(현재 · 기다리는 것 · 마지막 작업 · 다음 예상) · **진행 단계**(문의 초안 → 승인 → 발송 → 회신 · 추출 → 재평가 → 계획 → 결과, 기록된 단계로 체크) · **작업 기록**(시작 · 의미 있는 단계 · 멈춤 · 재개 · 종료만) · 원래 단계 · Tool 호출은 "기술 상세"로 접음
- API: `POST /agent-runs` · `/start` · `/resume` · `/cancel` · `/contact-selection` · `/registry/*`
- Error: `WRONG_COUNTERPARTY` · `NOT_WAITING_FOR_CONTACT_SELECTION` 등 쉬운 말

### SCR-07 정보 · 사실
- 영역: 필요한 정보 표(무엇 · 대상 · 상태 · 누구에게 물었나 · 답장 · 지금 값 · 확정) · 사실 목록(값 · 상태 · 출처 · 인용 · 후보) · [확인] · [거절] · [정정] · [철회] · 접힌 "직접 입력"(종류 · 대상 · 날짜 · 시간대 · 값 · 출처 메모)
- 조회: `GET /truth/facts` · 문의 · 준비도 조합(정보 공백 API 는 Agent 전용이라 화면이 다시 조합)
- Action: `POST /truth/events/{id}/confirm|reject|correct|revoke` · `POST /truth/facts/manual`
- 권한: 현장 담당자는 직접 입력만
- T-135: 표 제목 "확인이 필요한 정보"(정보 공백 N건 · 확정 전 N건). 사실 상태 짧은 말(기호 + 글자): ✓ 확정 · ◐ 임시 · ◔ 다시 확인 필요(AGING) · ◷ 오래되어 사용 주의(STALE) · ⊘ 철회 · ↻ 새 값으로 대체 · ⚡ 값 충돌 · ○ 값 없음

- T-144: 입항 일시처럼 값이 시각인 사실은 서울 시각("10-29 06:35")으로 보인다(숫자 그대로 보이지 않게). 사람이 이미 판단해 지금 충돌이 아닌 사실의 교차 확인 줄은 "공공 근거와 충돌했음 — 사람이 판단함(해소)". 할 일 · 사실 카드의 대상에 선박 이름 "선박명 (호출부호)". 충돌 중인 사실에 기댄 계획의 [이 계획 승인]은 Backend 가 409 로 막는다
- T-137: 할 일에 **"업체 회신과 공공 기록이 서로 다릅니다"**(종류 검토 · 대상 선박 / 입항 정보 · 업체 값 · 공공 값 · 차이 — 업체 값이 맞으면 확인, 공공 기록이 맞으면 거절). 사람이 아직 판단하지 않은 충돌만(`GET /truth/corroborations/open-conflicts`). 실행 사실 목록에 그 실행 회신이 주장한 입항 신고가 함께 나온다
- T-136: 입항 일시 사실 카드에 **공공 근거 교차 확인** 한 줄(일치 · 충돌 — 사람 검토 · 공공 근거 없음(거짓 아님) · 공공 근거 오래됨 · 비교 불가) + 업체 값 · 공공 값 · 차이(허용 오차는 가정값). 화면은 판정하지 않고 Backend 규칙 결과를 그대로 보인다
### SCR-08 연락 (+ 답장 검토)
- 영역: 문의 · [요청] · [정정] · [취소]와 답장을 시간 순서로 · 이전 계획 기준 초안 표시 · 항목을 펼치면 초안 화면(받는 사람 · 내용 · 구조화 값 · 숫자 검사 · Gate · [승인] · [반려] · [발송 요청]) · 답장(원문 미리보기 · 추출 시도 · 실패 이유 · 후보 · [다시 추출]) · 물은 정보가 이미 채워진 답장은 "✓ 처리 완료"
- 조회: `GET /communication/drafts*` · `GET /communication/inbound`
- Action: approve · reject · send · extraction retry
- 권한: 현장 담당자에게 "승인 · 발송은 운영자 · 관리자만" 안내
- Empty: 연락 없음
- T-135: 각 연락에 종류([문의] · [요청] · [정정] · [취소]) · 상태 · 상대 · 시각 · **계획 근거** 배지. 승인 대기 초안 위에 **"승인 전 확인"** 상자(보낼 대상 · 무슨 내용 · 근거 계획 · 숫자 검사 · 이전 요청과 달라진 점). 답장마다 "이 답장이 답하는 문의". 값을 못 얻은 답장 = "AI 가 이 답장에서 확실한 값을 찾지 못했습니다 — 원문을 확인한 뒤 직접 입력하거나 다시 분석할 수 있습니다(시스템 오류 아님)" + 이유 · 시도 횟수 · [다시 추출] · 직접 입력 안내

### SCR-09 복구 계획
- 영역: 입력 준비도(실제 실행 — 빠진 값 필드 단위) · 판 · KPI(총 예상 손실 · 기본 비용 · 기준안 · 절감 · Solver 상태) · 컨테이너별 조치 · OUTDATED 이유("다시 계산해야 합니다") · [지금 사실로 다시 계산] · [이 계획 승인]

- Action: `POST /planning/runs/{runId}/plans` · `POST /planning/plans/{planId}/approve`
- 비고: 승인은 배차 · 발송 지시가 아님을 화면에 표시
- T-135: 위에 숫자 카드(Baseline · 추천 · 예상 절감(시뮬레이션 기준) · 조치 수) + **Baseline 대 추천 막대 비교**(엔진 값 두 개의 길이만 — 새 숫자 · 백분율 없음). **OUTDATED** = 경고 상자 "이 계획 이후 계획이 기댄 정보가 바뀌었습니다 — 새 계획이 필요합니다" + 이유마다 Backend 가 남긴 값이 있으면 "기존 8 → 현재 6" + [다시 계산]. 계산 오류는 쉬운 말 + 기술 상세

- T-136: 조치 카드에 **예외 영향 범위** 한 줄 — "예외 영향 N대 재배치 후보(조치별 수) · 영향 없는 M대는 원래 계획 고정"(계획 항목 `detail.scope`). 예외 없이 연 실행은 표시하지 않는다
### SCR-10 변경 · 후속
