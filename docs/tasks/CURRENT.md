# Task: T-073 CERA Conceptual Data Model (개념 데이터 모델)

## Goal

**테이블이 아니라 개념과 관계를 정한다.** CERA가 현실에서 다루는 데이터가 각각 무엇인지 분류하고(독립 대상 / 속성 / 코드값 / 운영 사실·관측 / 현실 사건 / 현재 상태 / 계산 결과 / 계획·결정 / 외부 참조 / 근거·원문 / 범위 밖), 무엇으로 식별되며 무엇과 관계가 있는지, 원본인지 파생인지, 시간 축이 필요한지, MVP 필수인지를 확정한다.

## Why

- `docs/20`이 "테이블을 만들기 전에 무엇이 확정돼 있고 무엇을 더 결정해야 하는가"를 갈라 놓고 **개념 모델 착수 조건 충족**을 판정했다(18절). 그다음 단계가 이것이다.
- 개념 모델이 없으면 **`docs/04`(엔티티 표·ER)와 `docs/07` 4절(저장 스키마)을 고칠 수 없다.** `docs/20` 6.3절이 그 동기화를 "개념 모델 승인 뒤 한 번에"로 미뤄 뒀다(지금 고치면 두 번 고친다).
- 외부 통신 구현 계획(T-069)의 "최소 DB 스키마"도 여기에 기댄다. 물류 명사를 발견한 순서대로 테이블을 만들면 나중에 되돌리기 어렵다.
