# 10. Operations Simulator 요구사항 (현재 Prototype 구현: 2D SVG · Three.js는 향후 선택지)

- 상태: Draft (기획 v0.2)
- 최종 수정: 2026-09-15 (Prototype 구현 반영: 2D SVG, 신선도 UNKNOWN 인코딩, 데이터 계약)
- 관련 ADR: ADR-016(웹 + Three.js), **ADR-022(Next.js + 2D SVG, Proposed)**, ADR-018(시나리오 재생)
- 상세 명세: T-038

> **2026-09-15 Prototype 반영**: 이 문서의 요구사항 가운데 장면 구성(2절)·시각 인코딩(3절)·화면 배치(4절)·재생 모드(5절 재생)는 Control Tower Prototype(`16_frontend-prototype.md`)에서 **추상 2D SVG**로 먼저 구현했다. Three.js 2.5D는 쓰지 않았고(ADR-022), 필요하면 T-056에서 다시 판단한다. 데이터 계약(6절)은 SSE 대신 `as_of`를 주입하는 Provider 메서드(`16` 5절)로 구현했다. 실시간·영상 모드와 30fps 기준(7절)은 아직 해당 없음.

---

## 1. 목적과 비목적

| 목적 | 비목적 |
| --- | --- |
| Agentic Operations의 **상태 변화와 Recovery Plan**을 직관적으로 보여준다 | 실제 항만 디지털 트윈을 정밀하게 재현하는 것 |
| 현업 인터뷰·공모전 데모·30초 영상에 쓴다 | 물리 시뮬레이션(게이트 대기열, 크레인 동작) |
| "무엇이 틀렸습니까?"를 묻게 만드는 구체적 화면 | 실제 지도·축척 |

화면에 "시뮬레이션 — 실제 항만 배치가 아님"을 표시한다(`01_project-rules.md` 4절).

## 2. 장면 구성

| 요소 | 표현 | 데이터 출처 |
| --- | --- | --- |
| Terminal | 블록 영역 + 컨테이너 적재 칸 | 위치 사실 `TERMINAL` |
| Container | 박스(20ft/40ft 길이 차이). 인스턴싱으로 그림 | Canonical State |
| Truck | 작은 차량 모양. 경로를 따라 이동 | 계획 배정 + 시계 |
| ODCY A/B(/C) | 별도 야드 영역 + 용량 게이지 | 자원 사실 |
| Warehouse A | 건물 + 오늘 수용량 게이지(20 → 8) | 자원 사실 |
| Gate | 터미널 출구 | — |
| 이동 경로 | 도식적 도로 선(Terminal→Warehouse, Terminal→ODCY, ODCY→Warehouse) | 계획 경로 |

- 기본 카메라는 **2.5D 등각(orthographic)**이다. 자유 3D 회전은 선택 기능이다.
- 에셋은 기본 도형(박스, 원통)으로 만든다. 외부 3D 모델 파일에 의존하지 않는다.

## 3. 시각 인코딩

| 의미 | 표현 | 비고 |
| --- | --- | --- |
| 정상 | 기본 색 | |
| 위험 등급 HIGH·CRITICAL / 예외 영향 | **빨간 강조** + 외곽선 | 색만으로 구분하지 않고 아이콘·라벨도 함께 |
| 사실 상태 `freshness_status = STALE` / `conflict_status = OPEN` / `hold_status = HELD` | 점선 외곽 / 느낌표 아이콘 / 자물쇠 아이콘 | 클릭하면 근거(`explanation`) |
| 사실 상태 `freshness_status = UNKNOWN` (RECEIVED_ONLY, T-060) | "시각 모름" 점선 배지 + 수신 시각만 표시 | STALE(오래됨)과 다른 배지. 나이를 표시하지 않는다 |
| PROVISIONAL 입력 사용 | 반투명 경로 | 입력 사실이 확인(CONFIRMED)되면 실선. 계획 승인만으로는 바뀌지 않는다 |
| 경로 변경 | 이전 경로 흐리게 → 새 경로 강조 애니메이션 | Plan v1 → v2 |
| 자원 용량 | 게이지 막대(사용/가능) | 창고, ODCY, 트럭, 슬롯 |
| 금액 | 상단 카운터: Baseline 예상비용, Recovery 예상비용, Potential Saving | **엔진 결과만**. "시뮬레이션 기준" 라벨 |

## 5. 모드

| 모드 | 설명 |
| --- | --- |
| 실시간 | 백엔드 SSE를 따라 그린다 |
| 재생 | 시나리오를 시계 속도(1×~60×)로 재생·일시정지·되감기 |
| 데모 | 자동 진행 + 단계별 설명 자막(`09_mvp-scenario.md` 타임라인). 승인 단계는 자동 승인 또는 클릭 대기 선택 |
| 영상 | 데모 모드를 30초 분량으로 압축하는 고정 카메라 경로 |

## 6. 데이터 계약

- 프론트는 **표시만** 한다. 위치·경로·금액은 백엔드의 Canonical State, RecoveryRun, Agent Activity에서 온다. 애니메이션 보간만 프론트에서 한다.
- 초기 로드: `GET /state/containers`, `/state/resources`, `/recovery/runs/{active}`
- 갱신: `GET /stream` (SSE)의 `state.diff`, `activity`, `plan.updated`, `notification`
- 트럭 위치는 계획의 출발 슬롯과 경로 길이로 보간한 **표시용 추정**이다. 실제 GPS가 아니다.

## 7. 성능·품질 기준

| 기준 | 값 `[ASSUMPTION]` |
| --- | --- |
| 컨테이너 100개 + 트럭 10대 | 30fps 이상 (일반 노트북) |
| SSE 이벤트 → 화면 반영 | 1초 이내 |
| 예외 입력 → 빨간 강조 | 2초 이내 |
| 접근성 | 색 + 아이콘·라벨 병행, 텍스트 대비 확보 |

## 8. 수용 기준 (T-056)

1. `09_mvp-scenario.md`의 타임라인을 데모 모드로 끝까지 재생할 수 있다.
2. 11:00 예외에서 영향 12대가 강조되고, Plan v1 경로가 그려진다.
3. 회신 뒤 Plan v2로 경로가 바뀌는 애니메이션이 보인다.
4. 화면의 모든 금액이 Recovery Console과 같은 Run ID 값이다.
5. 타임라인 항목에서 관련 대상으로 이동할 수 있다.
6. 네트워크 없이(LLM 녹화 재생) 전체 데모가 돈다.
