# 01. 프로젝트 규칙

- 상태: Draft v0.1
- 최종 수정: 2026-09-10

이 문서의 규칙은 모든 에이전트와 사람 작업자에게 적용된다. 규칙을 바꾸려면 `09_decisions.md`에 ADR을 올린다.

---

## 1. 제품 원칙

1. **판정 AI가 아니라 운영 복구 AI다.** B/L, 컨테이너 식별, 통관 상태는 공공 시스템과 운영자가 확정한다. CERA는 확정된 상태를 받아서 이동·지연·예외 이후의 복구계획을 계산한다.
2. **총비용으로 비교한다.** "ODCY로 빼면 D&D가 사라진다" 같은 단일 비용 논리를 쓰지 않는다. 대안마다 `05_domain-model.md`의 총비용 모델로 비교한다.
3. **있어 보이는 기능보다 재현 가능한 계산.** 모든 추천은 입력·규칙·기준시각으로 다시 계산해 같은 결과가 나와야 한다.
4. **사람 승인 우선.** 실행(예약·배차)은 V1부터 사람 승인 뒤에만, 외부 쓰기 연동은 V2부터만 한다.

## 2. 검증 태그 규칙

문서, 설정 파일, 데이터 레코드의 출처 필드에 아래 태그를 쓴다.

| 태그 | 의미 | 예 |
| --- | --- | --- |
| `[VERIFIED]` | 공식·1차 출처에서 존재를 확인했다. 출처 URL과 확인일을 함께 적는다. | UNI-PASS 화물통관진행정보 API 존재 |
| `[ASSUMPTION]` | PoC를 위한 가정값이다. 근거와 바꿀 조건을 적는다. | ODCY 보관료 1일 N원 |
| `[TO VERIFY]` | 현업·제휴·법적·운영 검증이 필요하다. `10_open-questions.md`에 항목이 있어야 한다. | 선사별 Free Time 기산 기준 |

데이터 레코드의 출처 구분(`provenance.kind`)은 다음 값을 쓴다(`03_data-strategy.md` 6절).

| kind | 의미 |
| --- | --- |
| `PUBLIC_API` | 공공 API 응답에서 파생 |
| `USER_INPUT` | 사용자가 입력하거나 업로드 |
| `TARIFF_DOC` | 공개 Tariff 또는 계약 문서에서 구조화 |
| `SIMULATED` | 시뮬레이터가 생성한 가상값 |
| `DERIVED` | 엔진이 위 값들로 계산 |

규칙:
- 2차 출처(블로그, 커뮤니티)만으로는 `[VERIFIED]`를 붙이지 않는다. `[TO VERIFY]`로 두고 출처를 병기한다.
- 가정값을 코드에 하드코딩하지 않는다. 설정 파일이나 시나리오 파일에 두고 태그를 단다.
- 검증이 끝나면 태그를 바꾸고 `10_open-questions.md`의 해당 항목을 닫는다.

## 3. AI/LLM 역할 경계 (Hard Rule)

| 기능 | 담당 | 원칙 |
| --- | --- | --- |
| 상태·비용 계산 | Rule Engine | 결정론적 |
| 자원 배치 | Optimization Solver | 결정론적 |
| 계약 PDF 구조화 | LLM + 사람 승인 | 결과는 `TariffRule` 초안이며, 승인 전에는 계산에 쓰지 않는다 |
| 운영자 질의 해석 | LLM | 자연어를 제약조건(Constraint)으로 바꾸기만 한다 |
| 추천 이유 요약 | LLM | 숫자는 엔진 결과만 인용한다 |

- LLM 출력에 들어간 숫자는 반드시 엔진 결과에서 가져온 값이어야 한다. 구현할 때 엔진 결과를 구조화된 입력으로 넘기고, 출력 숫자가 입력에 있는 값인지 검사하는 테스트를 둔다.
- `tariff/`, `risk/`, `optimize/`, `cost/` 모듈은 LLM 클라이언트를 import하지 않는다.
- LLM 기능은 V0.2 이후에 붙인다. V0.1에는 LLM이 없다.

## 4. 확정하지 않을 주장 (금지 주장)

아래 문장은 코드 주석, UI 문구, 문서, 발표자료 어디에도 사실처럼 쓰지 않는다.

- "공공데이터만으로 LFD를 완벽하게 계산한다."
- "ODCY로 빼면 D&D가 제거된다."
- "project44는 경고만 하고 실행 기능이 없다."
- "외부 Agent가 부산항 VBS를 공개 Write API로 즉시 자동예약할 수 있다."
- "3개 대안 가격 비교 자체가 OR-Tools 최적화다."
- "완전 자율 배차가 MVP에서 가능하다."

## 5. 계산·데이터 규칙

1. **기준시각 주입**: 엔진 함수는 `as_of: datetime`을 인자로 받는다. `datetime.now()` 같은 현재시각 호출은 진입점(API, CLI, 스케줄러)에서만 한다.
2. **타임존**: 모든 시각은 `Asia/Seoul` 타임존이 붙은 값이다. 타임존 없는 datetime은 경계에서 거부한다.
3. **금액**: 원(KRW) 정수. 외화 Tariff는 환율과 환율 기준일을 함께 기록한 뒤 KRW로 바꾼다. 부동소수점 금액 연산은 금지한다.
4. **재현성**: 시뮬레이터와 솔버는 seed를 받는다. 실행 결과(Recovery Run)에는 입력 스냅샷 해시, 규칙 버전, seed, as_of를 저장한다.
5. **원본 보존**: 공공 API 원본 응답은 가공하지 않고 `fetched_at`과 함께 보관한다. 파싱은 원본을 다시 읽어서 재실행할 수 있어야 한다.
6. **출처 추적**: ContainerState의 모든 필드는 출처(kind, source, as_of)를 추적할 수 있어야 한다.

## 6. 보안·데이터 취급

- API 키는 `.env`에만 둔다. `.env`는 커밋하지 않고 `.env.example`만 커밋한다.
- 실제 B/L 번호, 컨테이너 번호, 화주명, 계약서는 커밋하지 않는다. 테스트 fixture는 식별자를 마스킹하거나 합성한다.
- `data/raw/`(실제 원본 응답)는 `.gitignore`에 넣는다. `data/fixtures/`에는 마스킹된 것만 둔다.
- V1 이전에는 외부 시스템에 대한 쓰기 요청(POST/PUT으로 예약·배차·신고)을 구현하지 않는다. 읽기 전용 클라이언트만 둔다.

## 7. 코드 규칙 (T-003에서 확정, 초안)

- 언어: Python 3.12. 타입힌트 필수. 도메인 모델은 Pydantic v2.
- 포맷·린트: ruff. 테스트: pytest.
- 식별자는 영어, 도메인 용어는 `08_glossary.md`의 영문 표준 표기를 쓴다(예: `lfd`, `free_days`, `odcy`).
- 엔진(`tariff`, `cost`, `risk`, `optimize`)은 순수 함수 위주로 짜고 I/O를 넣지 않는다.
- 새 엔진 로직에는 단위 테스트를 반드시 붙인다. 비용 계산은 손으로 검산한 예제를 테스트 케이스로 둔다.
- 외부 API 클라이언트는 원본 응답 fixture로 테스트한다. 테스트에서 실제 네트워크를 호출하지 않는다.

## 8. 작업 규칙

- 작업 절차는 `AGENTS.md` 3절을 따른다(선택 → 착수 → 수행 → 완료 및 큐잉 → 인계).
- 범위를 몰래 넓히지 않는다. 발견사항은 큐 또는 `10_open-questions.md`로 보낸다.
- 설계 결정은 ADR로 남긴다. 사소한 구현 선택은 LOG에만 적어도 된다.
- 문서 언어: 한국어. 코드·커밋 메시지: 영어 또는 한국어(한 저장소 안에서는 통일, T-003에서 결정).
- git 커밋은 사람이 요청하거나 태스크 완료 조건에 있을 때만 한다.
